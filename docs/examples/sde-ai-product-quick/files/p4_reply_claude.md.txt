## 4. Fixes

1. **"…it was recognized among the conference's top 100 accepted papers."** Change "the conference's" back to whichever venue actually ranked it, almost certainly the workshop, because a workshop paper in a main conference's top 100 will draw scrutiny.
2. **"Reduced ground truth data annotation time by 50% using AWS SageMaker and Supervisely…"** Name the metric that actually fell by 50% (time, cost or manual effort) and keep "time" only if that is what was measured.
3. **"Built a data extraction tool with Python and Selenium, reducing extraction time by 66% for 1,00,000 records."** Write "100,000" for a US reader, and if the 3-hour-to-1-hour bullet below is the same 66% result, merge the two into one bullet.
4. **"Built data solutions with MongoDB and SQL, increasing storage capabilities and project versatility."** Replace "storage capabilities and project versatility" with what was stored, at what volume and for whom, or cut the bullet.
5. **"Used Jupyter Notebook and Colab for data analysis and visualization."** Cut it, along with "Used JavaScript for web scraping and dynamic data extraction.": both are tool mentions with no outcome, and the tools already appear in Skills.
6. **"Developed a MOT model with Faster R-CNN and Graph Neural Networks for a self-driving application."** Spell out MOT (presumably multi-object tracking) and, if it was measured, add the accuracy gain the original mentions.
7. **"Computer science master's graduate with experience in deep learning, machine learning, data extraction, computer vision, and database development."** Lead with the 15 months as a deep learning engineer on a production autonomous-driving platform, and account for what they have been doing since May 2025, because a hiring manager will notice the gap.
8. **"Generative AI and LLMs, prompt engineering, NLP, deep learning…"** Listed first, these are the skills this role screens on, and no work bullet supports them. Either add a bullet for real LLM work they did, or reorder so the computer-vision skills they can defend come first. Add AI-assisted coding tools only if they actually use them.

## 5. Claim-defence questions

1. **"The 66% extraction-time cut and the 3-hours-to-1-hour scraping cut: are those the same project? What was the baseline, and how did you time it?"** Tests whether one result is counted twice and whether the candidate actually measured it.
2. **"You list a 50% annotation improvement and a 50% labeling-time reduction. What did each pipeline look like before, which parts did you build yourself, and are they the same system?"** Tests their own part versus the team's, and possible double-counting.
3. **"95% precision and recall: on which dataset and classes, at what IoU threshold, and compared with what baseline?"** Tests evaluation rigor and whether the number holds up outside a cherry-picked split.
4. **"Generative AI and LLMs is first in your skills. Walk me through something you built with an LLM: how you picked the model, how you evaluated it, and whether it reached users."** Tests the role's core must-have, which the resume does not evidence.
5. **"On the position paper with six authors, what did you write or build? And was the top-100 recognition from the workshop or the main conference?"** Tests their own contribution and the scope of the recognition.
