Python meets the listed language requirement; missing TypeScript alone is not a disqualifier. The central gap is demonstrated engineering scope.

**4. Fixes, in priority order**

These improve clarity and credibility; they cannot supply the missing senior/staff experience.

1. **“Technical Specialist leading end-user equipment imaging, deployment and lifecycle projects and providing escalation support. Earlier built and deployed a FastAPI API for real-time predictions on AWS ECS as a Machine Learning Engineer.”**  
   Lead with the supported software deployment and automation experience, then identify the current IT role, without implying additional years of software engineering or customer embedding.

2. **“Built and deployed a scalable API with FastAPI for real-time predictions on AWS ECS, which improved deployment efficiency by 30%.”**  
   Replace “deployment efficiency” with the actual measured quantity and baseline, and substantiate “scalable” with traffic, load testing or deployment architecture if available.

3. **“Lead IT projects for end-user equipment imaging, deployment and lifecycle management, with a 30% improvement in operational efficiency and a 25% increase in service quality.”**  
   Define the two metrics and their measurement periods, or remove percentages the candidate cannot explain with concrete evidence.

4. **“Provide escalation support for technical problems: 95% of critical systems had minimal downtime (under 2 hours) and fast recovery.”**  
   Clarify which systems were counted, whether “under 2 hours” means per incident or over a reporting period, and what recovery work the candidate personally performed.

5. **“Contributed to the design and implementation of new IT processes and systems, which cut process inefficiencies by 15% and improved service delivery.”**  
   Preserve “Contributed” while identifying one actual process change and replacing “process inefficiencies” with the measured outcome, or cut this generic bullet.

6. **“Automated end-user device imaging and deployment with SCCM and PowerShell scripts, which streamlined onboarding of new employees and cut deployment times by 30%.”**  
   Identify whether this is the same work described under the current role and consolidate it there if so, or add context that establishes it as a separate project.

7. **“Cloud: AWS (IAM, ECS, RDS, S3, Lambda, DynamoDB), Azure Logic Apps, Microsoft Azure (in progress)”**  
   Keep demonstrated tools and remove the broad “Microsoft Azure (in progress)” entry, which describes learning status rather than a defined skill.

8. **“Microsoft Azure Machine Learning (in progress)”**  
   As of 15 October 2026, confirm the current status and exact intended credential, retaining “in progress” only if still accurate and removing the entry if it is no longer being pursued.

**5. Claim-defence questions**

- **For the FastAPI service, what did you personally implement, who used it, and what did you own after deployment?**  
  Tests end-to-end production responsibility, individual contribution and operational depth.

- **What changed to produce the 30% improvement in “deployment efficiency,” and what were the before-and-after measurements?**  
  Tests whether the metric is defined, reproducible and attributable to the work.

- **Walk through one of the 150 complex issues: what was unfamiliar, how did you isolate the cause, and what permanent fix followed?**  
  Tests debugging depth and whether the work extended beyond routine support.

- **For the multimodal document platform, how did BERT and the CNNs interact, and how was the 40% processing-time reduction measured while checking output quality?**  
  Tests architectural understanding, evaluation discipline and the candidate’s actual implementation role.

- **Who defined the requirements for the ticket-routing automation, how did you handle exceptions and access permissions, and could another team adopt it without your ongoing help?**  
  Tests stakeholder discovery, deployment judgment and the ability to turn a local solution into something reusable.
